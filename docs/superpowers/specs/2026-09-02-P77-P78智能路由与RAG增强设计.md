# P77/P78 智能路由与 RAG 增强设计

## 目标

P77 将聊天运行时从订单场景硬编码升级为通用、可解释的结构化意图规划器，支持多意图、实体约束、工具/RAG/直接回答分流和澄清。

P78 在现有混合检索基础上增加查询改写、多查询融合、同义词扩展和真实 Cross-Encoder 重排，并将增强过程暴露给检索测试与 Trace。

## P77 架构

1. 工具增加意图编码、路由示例和必填实体配置，路由能力成为工具元数据而不是 Java 业务规则。
2. `IntentRoutingPolicy` 将用户输入按标点和连接词拆成多个子意图，使用工具名称、编码、描述、示例和参数名计算匹配度。
3. 规划结果包含意图、实体、候选工具、是否检索知识库、是否直接回答、是否需要澄清、置信度和解释。
4. Chat Runtime 在 RAG 和 Tool Calling 之前执行规划；工具模型只能看到规划器筛选后的工具，缺少必填实体时先澄清，不执行高风险动作。
5. 规划结果写入运行上下文、SSE 元数据和 Trace，调试台可以说明“为什么调用/为什么未调用”。
6. 移除订单、优惠券等具体业务词的硬编码判断，演示场景通过工具路由元数据表达。

## P78 架构

1. `QueryEnhancementPolicy` 保留编号、日期和专有名词，完成规范化、口语清理、同义词扩展和有限数量的查询变体生成。
2. 原查询与增强查询分别执行向量/BM25 召回，通过跨查询 RRF、最佳分数和命中次数融合，按分片 ID 去重。
3. 知识库配置了 `rerankModelId` 时，`CrossEncoderRerankService` 调用供应商标准 `/rerank` 接口；失败时降级到规则重排并记录原因。
4. 检索请求支持开关查询改写、多查询和最大变体数；检索结果返回实际查询变体、重排模式、模型和耗时。
5. Agent RAG 和检索测试共用同一条增强链路，避免线上与测试页效果不一致。

## 数据与兼容性

- 新增 Flyway `V056`，为 `tool_definition` 增加 JSON 路由元数据字段，并带中文表字段注释。
- 未配置路由元数据的旧工具仍使用名称、编码、描述和请求 Schema 参与匹配。
- 未配置重排模型或供应商不支持 `/rerank` 时保持可用，明确返回 `rule_fallback`，不伪装成真实模型重排。
- 新开关均提供兼容默认值，现有 API 请求无需立即修改。

## 验收标准

- “你好”不会调用订单工具；“查询 OAF-DEMO-1001 并说明退款政策”能拆成工具和知识检索两个意图。
- 需要订单号的工具在输入缺失订单号时返回澄清计划，不执行工具。
- 同义表达和多意图查询能够生成有限且去重的查询变体，多路召回结果按分片去重融合。
- 配置真实 Rerank 模型时可解析标准重排响应；网络或协议失败时自动规则降级。
- 调试台和知识库检索测试能看到路由解释、增强查询及重排状态。
